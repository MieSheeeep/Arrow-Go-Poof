# 2 项目介绍

介绍游戏规则、界面设计、主要功能和特色。

**游戏规则**：玩家每次点击一个箭头，程序检查它沿自身方向到棋盘边界之间的同行或同列位置。如果没有其他箭头，箭头立即从逻辑棋盘清除并飞出，原位置露出下方拼豆颜色；如果存在其他箭头，则返回首个阻挡箭头，箭头撞击、变红并回退，同时扣除一次失误机会。累计三次失误即失败，清除本关全部箭头即通关。

**界面设计**：窗口固定为 1200×800。开始界面是一张工作桌封面，内置 `START GAME` 按钮；游戏界面中心是放在桌垫内的箭头棋盘，顶部状态栏显示 `LEVEL 01/03`、倒计时进度条、三颗生命和右上角暂停键；暂停菜单提供继续、重开本关、返回主界面；通关页显示冻结的时间和逐颗弹出的星级，失败页显示 `TRY AGAIN` 或 `TIME UP`。

**主要功能和特色**：

- 棋盘不是常规方框，而是**不规则像素区域**：只有属于图案的像素格才放置箭头，图案外的背景为空，因此谜题轮廓自然呈现像素画的形状；
- 三个固定拼豆关卡：16×16 ENCHANTED APPLE、16×16 BEAD BALL、18×17 MOON KITTY，均按提交者提供的 `.px` 拼豆图案制作；
- 每关独立倒计时，按时间与失误次数结算 1～3 星；
- 飞出、碰撞（撞击变红回退）、扣心、星星逐颗弹出等动画；
- 暂停、重开本关、返回主界面、下一关等完整流程控制；
- 得分与连击：连续正确点击累计 combo 并加分，失误打断连击，HUD 实时显示得分与连击；
- 提示（HINT）、撤销（UNDO）、存档/读档（SAVE/LOAD）、自动求解（AUTO）；
- 运行时用波形合成音效，无需外部音频文件；
- 界面动画打磨：倒计时进度条平滑渐变、爱心跳动、连击弹跳、掉血红光、结算面板淡入等。

主要模块如下：

- `src/board.py`：纯规则层，负责网格校验、路径检测、点击结果和清除，不依赖 Pygame；
- `src/game.py`：负责生命值、失误次数、倒计时、开始/通关/失败/暂停状态、关卡索引和星级结算，并把规则结果转成动画；
- `src/animation.py`：不依赖 Pygame 的飞出、碰撞、扣心和星星弹出时间模型；
- `src/ui.py`：负责背景、棋盘、HUD、开始/结果/暂停面板、功能条和坐标映射，以及连击弹跳、进度条平滑等界面特效；
- `src/level_generator.py`：仅用于开发与测试，根据颜色掩码生成可解方向布局及其验证顺序，运行时不调用；
- `src/sound.py`：程序化生成短音效；
- `main.py`：负责 Pygame 初始化、事件分发、更新和绘制。



# 3 实现思路

说明箭头、方向和关卡如何表示，重点解释路径检测方法。

**箭头与方向的表示**：每个箭头只保留四个方向 `U/D/L/R`，用方向增量表示——向上 `(-1, 0)`、向下 `(1, 0)`、向左 `(0, -1)`、向右 `(0, 1)`。箭头只有单格、无长度无曲折。

**关卡的表示**：每个关卡由两张相同尺寸的二维网格表示——`arrow_grid` 存放箭头方向（`U/D/L/R` 为箭头，`.` 为已露出位置），`color_grid` 存放对应位置的拼豆颜色名。两处都是 `None` 的位置表示图案外的背景，因此棋盘是不规则像素区域，而不是填满的方框。三关的方向布局都在设计阶段由固定种子生成、验证可通关后冻结为 `levels.py` 中的常量，运行时不会随机变化，避免出现无解关卡。

**路径检测（核心）**：点击某个箭头后，从该位置沿其方向增量逐步遍历同行或同列：每走一格，若遇到另一个箭头就返回 `blocked` 和 blocker 坐标；若越过棋盘边界仍未遇到箭头，则返回 `clear`。这样一次点击就能区分“可以飞出”和“被阻挡”两种情况。

```python
def _find_blocker(self, row: int, col: int) -> tuple[int, int] | None:
    row_delta, col_delta = DIRECTION_DELTAS[self.arrow_grid[row][col]]
    row += row_delta
    col += col_delta
    while self.in_bounds(row, col):
        cell = self.arrow_grid[row][col]
        if cell is None:
            return None          # 越过图案边界，视为无阻挡
        if cell in ARROWS:
            return row, col      # 遇到第一个箭头，即 blocker
        row += row_delta
        col += col_delta
    return None
```

**分层与状态机**：整体按 Board / Game / UI 三层划分，规则、状态和显示相互独立。`Game` 维护 `START / PLAYING / CLEARED / FAILED / PAUSED` 五种状态；倒计时只在 `PLAYING` 状态累加，暂停、通关或失败后冻结，重开、下一关、返回菜单都清零。星级按时间与失误次数结算——零失误且在三星期限内为 3 星，一次失误内且在二星期限内为 2 星，其余通关记为 1 星——通关瞬间生成 `LevelSummary` 冻结结果，因此停留结果页不会继续计时或改分。

**逻辑判定与动画分离**：点击成功时 `Board` 立即把箭头改成 `.`，同时 `Game` 追加一个 `FlyOutAnimation`；因此动画期间仍可点击其他合法箭头，甚至允许同一帧存在多个飞行动画。碰撞动画期间原箭头仍在 `Board` 中，只有动画结束（`update` 返回 `is_finished`）时才把起点加入 `error_cells`，保证“撞击变红、回退后保持红色”的时间顺序。扣心同理：被阻挡时 `Game` 立即 `lives -= 1` 并记录失误，同时追加 `HeartLossAnimation`，让刚失去的那颗心在 HUD 上先放大闪烁再淡出，静态生命图标则随 `lives` 立即减少。

**动画时间模型（纯 Python）**：`src/animation.py` 里的动画类都不依赖 Pygame，只记录 `elapsed` 和 `duration`，靠 `progress`、`phase`、`offset_cells`、`scale` 等属性对外输出，因此可以用单元测试独立验证时序：

- `FlyOutAnimation` 分「蓄力」和「飞行」两段：蓄力阶段箭头先向后回拉约 0.16 格并轻微放大，飞行阶段用二次缓动（`1 - (1 - t)²`）加速，飞出距离按方向给到越过 1200×800 窗口边界，保证视觉上确实“飞出屏幕”；
- `CollisionAnimation` 分「接近 / 撞击 / 回退」三段，接近时向 blocker 移动，撞击瞬间 `color_state` 变为 `error`（红色），回退时沿原路返回；
- `HeartLossAnimation` 分「闪烁 / 淡出」两段，闪烁时放大并左右抖动，随后淡出；
- `StarRevealAnimation` 用「初始延迟 + 逐颗错开 + 弹跳」驱动结果页的星星依次弹出。

**UI 渲染与响应式特效**：`UI` 只负责渲染和坐标换算，所有装饰动画都挂在界面层，用墙钟时间（`pygame.time.get_ticks()`）驱动，不改动游戏逻辑。具体做法是：`UI` 在每一帧对比上一帧的 `combo / score / lives / state`，检测到变化就触发一次性特效，再结合连续的墙钟计算逐帧动画：

- **倒计时进度条**：显示比例逐帧向真实剩余比例平滑逼近（`ratio += (actual - ratio) * min(1, dt * 14)`），避免“一步跳”；填充做成左亮右暗的渐变，顶部加一条高光；剩余 25 秒内变黄、10 秒内变红并脉动光晕；
- **连击弹跳**：连击增长时，`xN` 数字用带回弹的缓动 `_ease_out_back` 放大并变色，同时分数旁浮起一个「+10」的加分气泡向上飘散淡出；
- **爱心跳动与掉血红光**：满血的心随墙钟轻微缩放“跳动”；掉血瞬间整屏叠加一层快速淡出的红光，配合单颗心闪烁淡出；
- **结算面板入场**：面板用垂直渐变 + 金色描边 + 阴影，进入结算状态时整体淡入、标题带回弹放大，数据以 TIME / MISTAKES / BEST COMBO / SCORE 的 2×2 格子呈现；
- 棋盘 hover 青色发光、消除瞬间的 reveal 辉光、提示框的双层脉动描边等，也都是纯界面层的装饰。

这些特效都尽量“可加可不加”，不改命中区域、不改测试锁定的坐标，因此不会影响已有 183 个测试。

### 4.3 界面美化与动画打磨

这是收尾阶段的一次完整 AI 协作。我直接把诉求丢给 Claude Code：“美化所有界面，包括通关结算、实时进度时间条、combo 显示、爱心的变化等等，使其有好的页面布置以及动画效果”。

AI 的流程很典型：它没有上来就改，而是先通读 `board.py / game.py / animation.py / ui.py / levels.py / sound.py` 和 `tests/`，然后跑了一遍 `pytest`，确认基线是 **183 通过**。接着它只改动 `src/ui.py` 一个文件——把单调的纯色结算面板换成垂直渐变 + 描边 + 阴影，把 180×7 的小时间条换成带渐变的玻璃质感进度条，给 combo 数字加了弹跳、给分数加了「+10」上浮气泡，给爱心加了跳动、给掉血加了整屏红光，还让结算面板有了淡入进场。

我拿到结果后重点检查了两件事：一是这些特效有没有破坏原有的命中区域（`result_primary_rect`、`pause_resume_rect` 这些测试锁定的坐标），二是会不会把游戏逻辑和 UI 搅在一起。结论是它把装饰动画全部放在界面层、用墙钟驱动，`game.py` 完全没动，所以 183 个测试原样通过。之后我自己跑了一遍试玩，微调了结算面板里数据格和星星之间的纵向间距——AI 第一版把它们排得有点挤。

这次协作让我最有感的是「先测后改」：如果 AI 直接闷头改样式，很可能把测试锁定的布局坐标改坏；而它先跑测试再动手，收尾时又跑一遍确认，省掉了我很多排查时间。

# 7 心得体会

总结 AI 带来的帮助、出现的问题以及自己的收获。

这次作业让我完整走了一遍“用 AIGC 协作做一个小游戏”的流程，最大的体会是：AIGC 明显提高了需求拆分、代码骨架、测试用例和 Bug 定位的速度，但生成结果不能直接当作最终答案，每一步都要本人验证。

印象最深的是飞出动画的 Bug。最初版本里箭头只移动固定的两格，逻辑上“有动画”，视觉上却根本没有飞出屏幕。这个问题单看代码和测试都很难察觉，是实际运行试玩后才发现的。于是我先补了一个失败的回归测试，再重新追踪 Board 清除、Game 动画列表和 UI 绘制之间的数据流，最终把飞出距离改成越过窗口边界的方向距离。这件事让我理解到：测试只能覆盖你想得到的错误，真正的问题往往要靠运行和试玩才能暴露。

分层设计也帮了很大忙。把 Board 的规则、Game 的状态和 UI 的渲染拆开后，动画的时间模型可以脱离 Pygame 单独测试，倒计时、扣心、星级结算这些逻辑也都能用纯 Python 单元测试覆盖，最终跑出 183 个通过的用例。没有这层边界，很多逻辑会散落在绘制代码里，既难改也难测。

收尾的界面美化又给我补了一课：AI 很擅长“先跑测试、再只改一个文件、最后再跑一遍测试”这种收着打的节奏，但它的审美和排版并不总是对的。结算面板第一版的数据格和星星挤在一起，是我自己试玩后觉得不对劲才去调间距。所以 AI 给我的是速度和候选方案，最终“好不好看、好不好玩”还是要由我本人跑起来判断。

总的来说，AI 更适合做协作型开发工具：它可以快速给出候选结构，但边界条件、交互体验、关卡可玩性和最终责任仍然需要本人通过测试和试玩确认。



# 8 扩展功能（附加分）

在完成基础要求后，可以自行增加一些功能，例如：

- 更多关卡或关卡选择；
- 得分、计时或星级评价；
- 提示功能；
- 撤销上一步；
- 保存游戏进度；
- AI 自动求解当前关卡；
- 更流畅的动画和音效；
- 将程序打包为可执行文件。

附加功能不作强制要求。基础功能的完整性和正确性比堆叠大量附加功能更加重要。

本次实际完成的扩展功能：

- **计时与星级评价**：每关独立倒计时，按完成时间与失误次数结算 1～3 星，通关页逐颗弹出星星；
- **多个关卡**：3 个固定拼豆关卡（16×16 附魔金苹果、16×16 精灵球、18×17 月亮 Hello Kitty）；
- **更流畅的动画**：飞出（蓄力 + 飞行轨迹）、碰撞（撞击变红后回退）、扣心闪烁淡出、星星逐颗弹出，以及倒计时进度条渐变、爱心跳动、连击弹跳、掉血红光、结算面板淡入；
- **暂停与重开**：暂停菜单支持继续、重开本关、返回主界面；
- **得分与连击（combo）**：连续正确点击累计连击并加分，失误打断连击，HUD 实时显示得分与连击；
- **提示功能**：点击 HINT 高亮一个当前可安全消除的箭头；
- **撤销上一步**：点击 UNDO 恢复最近一次消除的箭头（得分与连击一并回退），通关后也可撤销回到对局；
- **保存游戏进度**：点击 SAVE/LOAD 将当前关卡进度写入 `savegame.json` 存档或读档；
- **AI 自动求解当前关卡**：点击 AUTO 让程序按当前可消除顺序自动连续消除，直至通关；
- **音效**：飞出、碰撞、消除、失败等音效全部在运行时用波形合成，无需任何外部音频文件；
- **打包为可执行文件**：提供 `build_exe.bat` 一键生成 `dist\ArrowGoPoof.exe`，双击即可运行、无需安装 Python。

未实现：无——原计划中的音效、随机生成可通关关卡均已接入游戏；打包可执行文件已提供脚本。
