## 2. 项目介绍

玩家每次点击一个箭头，程序检查它沿自身方向到棋盘边界之间的同行或同列位置。如果没有其他箭头，Board 立即把它标记为已清除，Game 创建飞出动画；如果存在其他箭头，Board 返回首个 blocker，Game 立即扣除一次失误机会，CollisionAnimation 负责撞击、变红和回退。

项目包含 DIAMOND SWORD、BEAD BALL、MOON KITTY 三个关卡。每个关卡由二维网格和颜色网格表示：`U/D/L/R` 是四种方向箭头，`.` 是已露出的像素位置，`None` 是图案外背景。箭头清除后，原位置显示颜色网格中的拼豆颜色。三关均根据提交者提供的 `.px` 拼豆工程图案制作：钻石剑和精灵球为 16×16 固定网格，月亮 Hello Kitty 在设计阶段等比例压缩为 18×17；三个方向布局都通过固定种子生成、验证后复制为常量，因此每次启动布局相同，不会因随机生成而出现不可解关卡。

主要模块如下：

- `src/board.py`：纯规则层，负责网格校验、路径检测、点击结果和清除；
- `src/game.py`：负责生命值、失误次数、开始状态、关卡索引、通关和重开；
- `src/animation.py`：不依赖 Pygame 的飞出和碰撞时间模型；
- `src/ui.py`：负责背景、棋盘、HUD、开始/结果面板和坐标映射；
- `src/level_generator.py`：仅用于开发与测试；根据颜色掩码生成可解方向布局及其验证顺序，运行时不调用；
- `main.py`：负责 Pygame 初始化、事件分发、更新和绘制。

## 3. 实现思路

路径检测从点击位置沿方向增量遍历：向上使用 `(-1, 0)`，向下使用 `(1, 0)`，向左使用 `(0, -1)`，向右使用 `(0, 1)`。遇到第一个箭头就返回 `blocked` 和 blocker 坐标；越过棋盘边界仍未找到箭头则返回 `clear`。

逻辑判定和动画分离。点击成功时 Board 立即清除箭头，因此动画期间仍可以点击其他合法箭头；碰撞动画期间原箭头仍在 Board 中，只有动画结束时才把起点加入 `error_cells`，保证“撞击后变红，回退后保持红色”的时间顺序。

关卡的设计采用“先确定图案、再冻结布局”的方式：先用钻石剑、精灵球或 Hello Kitty 的颜色掩码确定可见轮廓；生成工具在仍存在的箭头中选择一条无阻挡射线，把该坐标加入清除顺序并记录方向。重复到所有格子被选中后，得到的顺序天然可通关。工具使用固定种子保证可复现，最终的箭头网格和通关顺序都写入 `levels.py` 常量，避免把随机性带进游戏运行时。

## 7. 心得体会草稿

AIGC 在需求拆分、代码骨架、测试用例和 Bug 定位方面明显提高了开发速度，但生成结果不能直接当作最终答案。例如最初的飞出动画只移动固定的两格，逻辑上虽然“有动画”，视觉上却没有真正飞出屏幕；通过实际运行发现问题后，重新追踪了动画数据流并补充回归测试。关卡数据也不能只看数组是否漂亮，还需要实际验证是否存在可行的清除顺序。

这次作业让我体会到，AI 更适合做协作型开发工具：它可以快速给出候选结构，但边界条件、交互体验、关卡可玩性和最终责任仍然需要本人通过测试和试玩确认。
