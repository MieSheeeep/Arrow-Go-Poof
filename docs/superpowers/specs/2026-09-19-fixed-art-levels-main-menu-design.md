# 固定图案关卡与主界面设计

## 目标

提升课程作业版本的视觉完成度和关卡质量：将 FLOWER、SUN 从小型网格替换为清晰的大型像素图案；让箭头方向在视觉上更分散；保持每次运行关卡完全一致且可解；把简单开始弹窗升级为正式主界面。

## 关卡策略

运行时不做随机生成。每个关卡的图案轮廓、颜色和箭头方向都固定在 `src/levels.py` 中，因此同一关卡在开始、重开和不同电脑上保持一致。

方向布局在开发阶段通过确定性生成器产生：每个关卡使用固定 seed 和既定像素掩码。生成器只产出上、下、左、右单格箭头，并同时记录一条完整清除顺序：

- 每个有效格要么是箭头，要么是已露出的 `"."` 像素；
- 四个方向均至少出现一次；
- 能够找到完整清除顺序；
- 难度不依赖运气，重开后布局不变。

验证通过的方向网格和清除顺序将被固化为元组常量。生产游戏只使用方向网格；生成器和清除顺序仅作为开发/测试工具，不参与玩家运行时逻辑。

## 图案关卡

关卡顺序保持 TREE → FLOWER → SUN：

- TREE：保留现有 12×13 树形轮廓，作为第一关；
- FLOWER：升级为 13×13 花朵轮廓，包含浅色花瓣、深色花瓣、花心、茎和叶片；
- SUN：升级为 13×13 太阳与地平线轮廓，包含圆形太阳、八向放射光芒、天空和草地。

每个图案至少有 50 个箭头，既保证视觉上像完整像素画，也让箭头方向排列有足够变化。颜色网格和箭头网格继续使用相同的 `None` 掩码。

## 主界面

主界面是独立的开始状态，而不是结果面板复用：

- 以完整窗口背景、装饰性箭头棋盘和大标题作为视觉中心；
- 显示一句规则提示：点击没有阻挡的箭头，让它飞出棋盘；
- 仅提供一个 `START GAME` 按钮；不增加关卡选择或额外菜单；
- 进入游戏后保持当前 HUD、棋盘、动画和结果流程。

## 数据流

```text
固定 seed + 图案掩码（仅开发阶段）
  ↓
生成顺序验证并冻结为 LEVEL 常量
  ↓
Game 从 LEVEL_FACTORIES 创建独立 Board
  ↓
UI 根据 START / PLAYING / CLEARED / FAILED 绘制主界面或游戏界面
```

## 测试与验收

- 验证花朵和太阳的尺寸、图案关键像素、箭头数和四向覆盖；
- 验证关卡常量不依赖运行时随机数；
- 使用求解器验证三个关卡均存在完整清除序列；
- 验证主界面可绘制，开始按钮进入第一关；
- 运行完整 pytest、编译检查和 Pygame dummy 主循环 smoke test；
- 生成更新后的主界面、花朵、太阳截图并更新 README/课程报告。
