# “一箭又一箭”可游玩 MVP 设计

## 1. 目标与范围

第二阶段将第一轮的纯 `Board` 规则扩展为一个可以直接运行和操作的 Pygame MVP。运行 `python main.py` 后，程序直接打开固定大小的游戏窗口并进入树形示例关卡。

本阶段包含：

- 1200×800 固定窗口；
- 简化像素风自然背景；
- 树形不规则演示关卡；
- 棋盘绘制、鼠标点击和坐标映射；
- 三点生命值、失误次数和剩余箭头显示；
- 成功飞出动画；
- 阻挡箭头的撞击、变红和回退动画；
- 通关、失败和重新开始结果面板；
- `Game` 状态层及对应单元测试。

本阶段不包含主菜单、计时、星级、Combo、音效、完整暂停流程、多关卡选择、真实像素图片资源和复杂粒子效果。

## 3. 模块职责

### `src/board.py`

继续作为纯规则层。它负责网格校验、路径判定、点击结果、箭头清除、剩余数量、通关判断和重置，不依赖 Pygame，不负责生命值、动画或页面状态。

### `src/game.py`

新增 `Game` 状态协调器，持有当前 `Board`、生命值、失误次数、游戏状态、动画列表和错误标记。它接收逻辑坐标，调用 `Board.click()`，根据结果更新游戏状态并创建动画数据。

建议的游戏状态为：

- `PLAYING`：允许点击箭头；
- `CLEARED`：棋盘清空，显示通关面板；
- `FAILED`：生命值归零，显示失败面板；
- `PAUSED`：保留状态接口，但本阶段不实现完整暂停流程。

### `src/animation.py`

定义不依赖 Pygame 绘制细节的非阻塞动画状态。动画保存点击瞬间的视觉快照，使用 `delta_time` 更新进度，不修改 `Board`。

- `FlyOutAnimation`：从原格沿箭头方向飞向棋盘外；
- `CollisionAnimation`：向首个 blocker 移动、撞击变红、回退到原位。

多个动画可以同时存在，动画期间不锁定棋盘。

### `src/ui.py`

负责窗口绘制、输入转换和结果面板。它绘制背景、树形棋盘、箭头格、HUD、动画和结果面板，但不直接改变 `Board` 或生命值。

### `src/levels.py`

保留当前小型测试关卡，并新增树形演示关卡工厂。树形关卡使用 `None` 表示不属于像素图轮廓的区域，颜色层表示树叶、树干和草地底色。工厂每次返回独立的 `Board`。

### `main.py`

初始化 Pygame，创建树形演示关卡、`Game` 和 `UI`，运行固定窗口的主循环。主循环负责读取事件、调用游戏更新、绘制画面和限制帧率。

## 4. 运行数据流

```text
鼠标点击
  ↓
UI 将像素坐标转换为 (row, col)
  ↓
Game 调用 Board.click()
  ├─ 成功：Board 立即清除箭头，创建 FlyOutAnimation
  ├─ 阻挡：立即扣生命，创建 CollisionAnimation，记录红色错误格
  └─ 非法/已清除：不扣生命，不创建动画
  ↓
Game 检查 Board.is_cleared() 与剩余生命
  ↓
UI 绘制最新棋盘、HUD、动画或结果面板
```

逻辑判定与视觉动画严格分离。成功箭头在点击返回前已经从棋盘状态清除，因此飞出期间可以继续点击其他箭头；阻挡箭头仍然存在于棋盘上，可以继续尝试点击。

## 5. 点击与状态转换

初始状态为：

- `state = PLAYING`；
- `lives = 3`；
- `mistakes = 0`；
- 动画列表为空；
- 错误标记为空。

点击规则：

| 点击结果 | 逻辑处理 | 视觉处理 |
| --- | --- | --- |
| `clear` | 保持生命值，棋盘立即清除箭头 | 创建飞出动画 |
| `blocked` | 生命值减 1，失误次数加 1 | 创建撞击回退动画，错误格变红 |
| `out_of_bounds` | 状态不变 | 无 |
| `invalid_cell` | 状态不变 | 无 |
| `already_cleared` | 状态不变 | 无 |

阻挡操作的时间顺序是：点击时立即完成判定和扣血；箭头向首个 `blocker` 移动；抵达 blocker 时变红；箭头回退到原位；动画结束后原位继续保持红色。红色错误标记在本关重置前保留。

生命值降为 `0` 后立即进入 `FAILED`，不再接受普通箭头点击。最后一支箭头成功清除后进入 `CLEARED`。重新开始会重新创建或重置棋盘，并清空生命值、失误次数、动画列表和所有错误标记。

## 6. 窗口与视觉布局

窗口固定为 `1200×800`。棋盘区域约位于 `x = 260..940`、`y = 130..690`，每个逻辑格约为 `48×48` 像素，实际绘制时由布局常量统一计算。

视觉分层如下：

1. 浅蓝天空背景；
2. 远山、草地和少量云朵/树影；
3. 树形关卡底色；
4. 箭头格和箭头图形；
5. 飞出、撞击和悬停反馈；
6. 顶部 HUD；
7. 通关或失败半透明结果面板。

棋盘格规则：

- 有效且仍有箭头：浅灰或米白方格，绘制深灰方向箭头；
- 已清除的有效格：绘制树叶、树干或草地底色，不绘制箭头；
- `None`：只显示背景，不绘制格子；
- 鼠标悬停格：增加浅蓝描边；
- 错误格：红色底色和深红箭头，动画结束后保留。

HUD 使用深蓝色横条，显示 `LEVEL 01`、生命值、失误次数和剩余箭头数量。结果面板位于中央，保留背景和棋盘，显示通关/失败文字、统计信息和“重新开始”按钮。

## 7. 动画接口约束

动画必须提供可测试的生命周期接口，至少包含：

- 当前进度或阶段；
- `update(delta_time)`；
- `is_finished`；
- 用于 UI 绘制的当前位置、颜色和透明度数据。

`FlyOutAnimation` 使用起点、方向和飞出距离计算位置。`CollisionAnimation` 使用起点和 blocker 坐标计算撞击点，并在阶段切换时改变颜色。动画完成后由 `Game` 移除，不得重复处理同一个逻辑点击。

## 8. 测试策略

新增 `Game` 和动画相关单元测试，保持测试不依赖真实窗口或人工点击：

- 初始状态、3 点生命值和示例关卡加载；
- 成功点击立即减少 Board 的剩余箭头；
- 成功点击创建飞出动画；
- 阻挡点击立即扣生命和增加失误次数；
- 阻挡点击记录 blocker 并创建撞击动画；
- 红色错误标记在动画完成后保留；
- 非法点击不扣生命、不创建动画；
- 生命值归零后进入 `FAILED` 并拒绝普通点击；
- 清空棋盘后进入 `CLEARED`；
- 重新开始恢复棋盘、生命值、失误次数、动画和错误标记；
- 多个成功动画可以同时更新；
- 1200×800 下鼠标坐标能映射到正确逻辑格。

最终验证包括：

```text
python -m pytest -v
python -m compileall -q main.py src tests
python main.py
```

并进行一次手动窗口验收：成功点击、阻挡点击、连续点击、生命耗尽、通关和重新开始。

## 9. 验收标准

运行 `python main.py` 后：

1. 打开 1200×800 窗口并直接进入树形演示关卡；
2. 棋盘、HUD 和简化像素风背景正常显示；
3. 点击可飞出的箭头时，逻辑立即清除并播放向外飞出的动画；
4. 点击受阻箭头时，立即扣生命，箭头撞向首个 blocker，撞击时变红，回退后原位保持红色；
5. 飞行动画或撞击动画期间可以继续点击其他箭头；
6. 生命耗尽显示失败结果面板并停止普通操作；
7. 清空棋盘显示通关结果面板；
8. 点击重新开始后恢复完整初始状态；
9. 现有 Board 测试和新增 Game 测试全部通过。
