# 课程作业博客整理设计

## 目标

将 `docs/course-report.md` 整理为可发布到博客园的课程作业博客，内容基于项目当前实现、已有运行截图和测试结果撰写。

## 结构约束

保留既有章节序号及顺序，不新增、删除、移动或重编号以下章节：

1. 项目展示
2. 项目介绍
3. 实现思路
4. AIGC 使用过程
5. 测试结果
6. PSP 表格
7. 心得体会

作业信息表也保持原有字段与顺序。

## 内容策略

- 第 1 节使用现有开始、游戏、暂停、通关与失败截图，并更新说明为当前封面点击热区、倒计时和结算效果。
- 第 2 节说明不规则有效区域、颜色网格、三关像素图和玩法规则。
- 第 3 节强调 Board/Game/Animation/UI 分层、成功点击即时改写 Board、阻挡动画、扣心、倒计时、星星依次出现及固定可解关卡。以短小的真实代码节选说明：Board 找到首个 blocker 并即时清除、Game 将规则结果转成动画、提示系统从 `first_clearable_arrow()` 到 UI 高亮的只读数据流，以及飞出动画如何把逻辑格位移换算成像素位置。
- 第 3 节加入“实现中的一次挫折与改进”小节，按“现象 → 定位 → 修改 → 回归测试”记录飞出箭头仅移动两格、视觉上突然消失的问题；说明后来改成朝窗口外飞行，并以动画距离测试防止回归。
- 第 4 节仅记录实际发生的 AIGC 协作与人工决策，不虚构过程或成果。
- 第 5 节更新测试覆盖范围与最新通过数；以执行结果为准。
- 第 6 节保留实际耗时待填写提示，不由 AI 填写。
- 第 7 节以具体问题、验证方式和个人责任为主线完成复盘。

## 待填写信息

课程名称、课程链接、作业链接、学号和 PSP 实际耗时均保持明确的待填写标记。

## 验证

- Markdown 标题序号和既有章节顺序不变。
- 截图使用 `docs/assets/` 下的现有文件，以相对路径插入。
- 博客中的功能描述与当前代码一致。
- 代码仅摘录本项目中有代表性的短段落，配合说明其作用；不堆砌完整文件，也不复制参考文章的实现。
- 不复制参考文章的文字、图片或代码。
