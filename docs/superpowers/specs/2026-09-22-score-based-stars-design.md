# 按得分结算星级设计

## 目标

将每关通关星级从“用时与失误次数”改为“本关最终得分占理论最高分的比例”。倒计时仍用于超时失败，失误仍通过中断连击降低得分，但两者不再直接参与星级判断。

## 评分规则

设关卡初始箭头数量为 `N`。每次成功消除的基础得分为 `10 × 当前连击`；若全程无阻挡且连续消除，理论最高分为：

```text
max_score = 10 × (1 + 2 + ... + N) = 5 × N × (N + 1)
```

通关时按本关的 `score / max_score` 判定：

| 得分比例 | 星级 |
| --- | --- |
| `>= 0.85` | 3 星 |
| `>= 0.60` 且 `< 0.85` | 2 星 |
| `< 0.60` | 1 星 |

`score` 和 `max_score` 均为单关数据；当前游戏每次加载、重开或切换关卡已经重置 `score`，不引入跨关累计分数。

## 结构调整

- `Game` 在关卡加载后读取 `Board.remaining_arrows()`，据此保存该关的理论最高分。
- 用以分数为输入的私有星级函数替换旧的 `_stars_for(elapsed_seconds, mistakes, limits)`。
- `LevelSummary` 新增通关时冻结的 `score` 与 `max_score`，保留 `elapsed_seconds`、`mistakes` 作为结果页统计信息。
- 移除 `Game` 的时间星级阈值配置；`src/levels.py` 不再提供 `LEVEL_STAR_THRESHOLDS`，`main.py` 不再传递该配置。
- UI 继续显示 TIME、MISTAKES、BEST COMBO、SCORE 和星星；不需要新增界面控件。

## 测试

- 满连击完成关卡，得分等于理论最高分，获得 3 星。
- 构造临界得分，验证 85% 与 60% 分别得到 3 星与 2 星；低于 60% 得到 1 星。
- 同一得分在不同 `elapsed_seconds`、`mistakes` 下得到相同星级，证明旧规则不再直接影响结算。
- 运行现有游戏、关卡和 UI 测试，确认 `LevelSummary` 与结果页仍能正常工作。

## 范围

本次不改变每次消除的得分公式、Combo 重置规则、超时失败规则或结果页布局；也不实现跨关总分排行榜。
